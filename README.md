# CS Browser Service

خدمة مستقلة فيها متصفح Chromium حقيقي لمساعد Odoo الذكي (Implementation والدعم الفني والمبيعات). يفتح المساعد بها صفحات الويب ويقرأها ويصوّرها، ويسجّل الدخول إلى Odoo العملاء، ويختبر الشاشات كما يفعل المستخدم.

- **قراءة البيانات وتعديلها** تبقى عبر الـ API.
- **المتصفح** للتحقق من الشاشات والتقارير والموقع والبوابة، ولإعادة تنفيذ المشاكل والاختبارات.

هذه الخدمة منفصلة عن خدمة المستندات (`ai_document_service`): مستودع مستقل، وStack مستقل، وتوكن مستقل.

## النشر على Portainer

1. ارفع محتوى هذا المجلد إلى مستودع **خاص** في GitHub، بحيث يكون `docker-compose.yml` في **جذر** المستودع (وليس داخل مجلد).
2. في Portainer: **Stacks > Add stack > Repository**:
   - **Repository URL:** رابط المستودع، مع توكن GitHub إذا كان خاصاً.
   - **Repository reference:** `refs/heads/main`
   - **Compose path:** `docker-compose.yml`
3. في **Environment variables** أضف `BROWSER_TOKEN` بقيمة سرية طويلة.
4. اضغط **Deploy the stack**. البناء الأول يستغرق بضع دقائق، لأن صورة Playwright كبيرة (حوالي 2 GB).
5. للتحقق افتح `http://IP:8687/health`: يجب أن تظهر `"status": "ok"` وإصدار Chromium.

| المتغير | الافتراضي | الوصف |
|---|---|---|
| `BROWSER_TOKEN` | فارغ | توكن الخدمة. بدونه تُرفض كل الطلبات |
| `BROWSER_PORT` | 8687 | المنفذ على السيرفر |
| `BROWSER_MAX_SESSIONS` | 6 | عدد المتصفحات المفتوحة في نفس الوقت |
| `BROWSER_IDLE_MINUTES` | 15 | يُغلق المتصفح بعد هذه المدة بدون استخدام |

## الإعداد في Odoo

من **AI > Configuration > Settings > Browser service**:

| الإعداد | القيمة |
|---|---|
| URL | `http://172.17.0.1:8687` إذا كان Odoo على نفس السيرفر، أو `http://IP:8687` |
| Token | نفس قيمة `BROWSER_TOKEN` |
| Allowed sites | المواقع المسموح فتحها، مثل `mycompany.com, customer.odoo.com` |

اضغط **Test connection**. يجب أن تظهر رسالة تحتوي إصدار Chromium.

## الدخول والاختبارات

- **الدخول التلقائي:** عندما يفتح المساعد صفحة من سيرفر قاعدة بيانات العميل المرتبطة بالمحادثة، يسجّل المتصفح الدخول بنفسه.
  - يستخدم حقلي **Browser login / Browser password** في سجل الاتصال، وإذا كانا فارغين يستخدم بيانات الاتصال نفسها.
  - مفتاح الـ API لا يصلح لدخول الواجهة، فالأفضل مستخدم دعم مخصص بكلمة مرور.
  - كلمة المرور تُرسل للخدمة فقط ولا يراها الذكاء الاصطناعي.
- **التفاعل:** يضغط المساعد ويكتب ويختار من القوائم ويضغط المفاتيح، مثل المستخدم.
- **لا تغيير بدون موافقة:**
  - أي طلب يغيّر البيانات في Odoo يُرفض: الحفظ، والتأكيد، والحذف، وأزرار السجلات، والإجراءات، والرسائل.
  - هذا يشمل الحفظ التلقائي عند مغادرة النموذج.
  - الأزرار الواضحة (Save, Confirm, Delete, حفظ, تأكيد, ترحيل...) لا تُضغط أصلاً، بل يتحول الضغط إلى **طلب موافقة** في المحادثة. بعد موافقتك يُنفذ هذا الضغط وحده.

## الأمان

- لا يفتح المتصفح إلا المواقع المسموحة:
  - المواقع المكتوبة في الإعدادات.
  - سيرفر قاعدة بيانات العميل المرتبطة بالمحادثة.
- أي رابط أو تحويل (redirect) أو إطار لموقع آخر يُحظر، وكذلك عناوين الشبكة الداخلية.
- لا تحميل ملفات، ولا حفظ أي شيء على القرص. لكل محادثة متصفح مستقل بكوكيز خاصة به.
- كل لقطة شاشة تُرفق في المحادثة، فيرى المستشار ما رآه المساعد بالضبط.
- محتوى الصفحات يُعامل كبيانات وليس كتعليمات للمساعد.

## الواجهة البرمجية

| الطلب | الوصف |
|---|---|
| `GET /health` | الحالة، وإصدار Chromium، وعدد الجلسات المفتوحة |
| `POST /v1/sessions` | `{"allowed_hosts": [...], "locale"}` ← `{"session_id"}` |
| `POST /v1/sessions/{id}/open` | `{"url"}` ← نص الصفحة وعناصرها المرقّمة |
| `GET /v1/sessions/{id}/read` | قراءة الصفحة مرة أخرى |
| `POST /v1/sessions/{id}/screenshot` | `{"full_page"}` ← صورة PNG بصيغة base64 |
| `POST /v1/sessions/{id}/login` | `{"url", "db", "login", "password"}` ← تسجيل الدخول |
| `POST /v1/sessions/{id}/act` | `{"action": "click\|type\|select\|press", "ref", "text", "allow_changes"}` |
| `DELETE /v1/sessions/{id}` | إغلاق المتصفح |
